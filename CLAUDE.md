# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Interior Designer AI is a Next.js 16.4 App Router application that redesigns room photos with a ControlNet model on Replicate. A user uploads a photo, picks a design theme, room type and style strength, compares the result with the original on a slider, downloads it, and can save it to a public gallery stored in Vercel Blob. A password-protected `/admin` page moderates the gallery.

Stack: React 19.3, TypeScript 6 (strict), Tailwind CSS 4.3 (configured in CSS), shadcn/ui on Radix UI, zod 4, Bun as package manager, test runner and local runtime (on Vercel the functions run on Node.js, see Deployment).

## Development Commands

### Essential Commands

- **Start dev server**: `bun dev` runs `portless interior-design bun --bun next dev` and serves https://interior-design.localhost. portless must be installed globally (`bun install -g portless`); it proxies to a port it assigns, so the app is not on localhost:3000.
- **Build production**: `bun run build` (plain `bun build` is Bun's bundler, not this script)
- **Start production**: `bun run start` (after a build)
- **Lint**: `bun run lint` / `bun run lint:fix` (oxlint)
- **Format**: `bun run format` / `bun run format:check` (oxfmt)
- **Test**: `bun test` (Bun's built-in runner; see Testing below)
- **Type-check**: `bun run typecheck` (the app, then the tests in `tests/`); `bunx tsc --noEmit` checks the app only

The `dev`, `build` and `start` scripts run Next.js on the Bun runtime (`bun --bun next ...`).

### Package Management

- Bun only; the lockfile is `bun.lock`. Never use npm, npx, yarn or pnpm.
- **Install dependencies**: `bun install` (also installs the Husky hooks through the `prepare` script)
- **Add dependency**: `bun add <package>` / dev dependency: `bun add -d <package>`
- **Remove dependency**: `bun remove <package>`
- **Execute package binary**: `bunx <command>`
- Read "Dependency Maintenance" below before upgrading anything.

### Environment Setup

Copy `.env.example` to `.env.local` and set:

- `REPLICATE_API_TOKEN`: Replicate API token, used by `app/api/replicate/route.ts`. Without it generation fails.
- `BLOB_READ_WRITE_TOKEN`: Vercel Blob read-write token, read implicitly by `@vercel/blob` (`put`, `list`, `del`). Without it the gallery and admin pages show no designs and saving returns 500.
- `GALLERY_ADMIN_SECRET`: the `/admin` password. The signing key for the admin session cookie is derived from it. Without it every sign-in returns 401. Changing it invalidates all existing admin sessions.

Optional: `GENERATION_DAILY_LIMIT` (default 200) and `GALLERY_SAVE_DAILY_LIMIT` (default 10) set the daily budgets in `lib/rate-limit.ts` (0 turns the feature off); `TRUSTED_IP_HEADER` names the client-IP header to trust when self-hosting (on Vercel `x-real-ip` is used automatically).

`.gitignore` ignores every `.env*` file except `.env.example`.

### Key Architectural Patterns

**1. Client-side state**

- No state library. The Design page (`app/(main)/page.tsx`) holds the uploaded image (data URL), the output (`{ image, theme, room }`: the design URL with the theme and room it was generated for, which "Save to gallery" uses instead of the current controls), the loading flag and the error in `useState`.
- Theme, room and scale come from `useSettings()` (`hooks/use-settings.ts`). Changing them on the Design page also updates the saved defaults.
- `useSettings` stores `{ theme, room, scale }` in localStorage under `interior-designer-settings`. Defaults are Modern / Living Room / `SCALE_DEFAULT` (9). Stored values are read in an effect after mount (the first render uses the defaults), sanitized against `DESIGN_THEMES`, `ROOM_TYPES` and `SCALE_MIN`..`SCALE_MAX` by `parseStoredSettings()` in `lib/settings.ts`, and written on every change; storage errors are ignored. Each call has its own state; it is not a shared store.
- Appearance (light/dark/system) is next-themes with `attribute="class"` and `defaultTheme="system"`. The settings page only highlights the active option after hydration (`useSyncExternalStore`).

**2. Unsaved-design navigation guard**

- `DesignProvider` wraps the `(main)` layout. The Design page copies its `outputImage` into the context in an effect and clears it on unmount.
- `AppSidebar.handleNavClick` (used by every nav link and the logo) cancels navigation when an output image exists and the target differs from the current path, then opens the "Unsaved Design" dialog (Stay / Download / Leave anyway). The dialog keeps its own copy of the image URL, so Download still works if the Design page unmounts while it is open.
- "Leave anyway" calls `router.push`, then `setOutputImage(null)` to disarm the guard. Only sidebar links are guarded.
- Every navigation from the sidebar (direct or "Leave anyway") calls `setOpenMobile(false)`, because a `Link` click does not close the mobile sidebar Sheet by itself.

**3. Image processing flow**

1. **Upload**: `useDropzone` accepts `image/jpeg` and `image/png` up to `MAX_FILE_SIZE` (5MB), checked by `validateUploadFile()` in `lib/upload.ts`. `ImageDropzone` then calls `prepareUploadImage()` (`lib/upload-image.ts`), which decodes the photo with `createImageBitmap` (applying its EXIF orientation), scales it so the longer edge is at most `MAX_UPLOAD_EDGE` (2048px) and re-encodes it as a JPEG data URL no longer than `MAX_IMAGE_DATA_URL_LENGTH`. The original file is never uploaded: Vercel rejects request bodies over 4.5 MB.
2. **Generate**: the page POSTs `{ image, theme, room, scale }` to `/api/replicate`. `generationErrorMessage()` in `lib/generation.ts` picks the error text, with fallbacks for error bodies that are not JSON (e.g. 413, 504 from the platform).
3. **Model**: the route runs `jagilley/controlnet-hough` (see Replicate API Integration).
4. **Display**: `pickDesignImage()` in `lib/generation.ts` takes `output[1] || output[0]` (the model returns the control map first); the page keeps the image together with the theme and room it was generated for, shows a toast and renders `ImageComparison` (react-compare-slider) with Original / AI Design labels. While loading, `OutputImage` shows staged progress messages and an elapsed timer.
5. **Download**: `file-saver` `saveAs(url, "interior-design.png")`, from the comparison toolbar or the guard dialog.
6. **Save**: "Save to gallery" POSTs `{ imageUrl, theme, room }` to `/api/gallery`, with the theme and room the design was generated for, not the current values of the controls.

**4. Gallery and admin**

- Saved designs live in Vercel Blob at `designs/<Date.now()>_<encodeURIComponent(theme)>_<encodeURIComponent(room)>.png`. The name always ends in `.png`; the stored content type comes from the sniffed bytes.
- `listDesigns()` in `lib/gallery.ts` follows Blob's pagination (1000 blobs per `list()` call), decodes theme and room from each pathname and sorts newest first. `encodeDesignPathname()` / `decodeDesignPathname()` in the same file define the name format.
- Every Blob `list()` is a metered operation (the Hobby plan includes 2,000 a month and then blocks the store), so `/gallery`, which anyone can request, uses `listDesignsCached()`. It wraps the listing in `unstable_cache` (tag `designs`, refreshed every 6 hours) and merges concurrent misses within the server process, because `unstable_cache` does not. The listing in flight is kept on `globalThis`: Next.js bundles pages and route handlers separately, so a module-level variable would not be shared between `/gallery` and the save and delete handlers. `revalidateDesigns()` drops the cache and is called after every successful save and delete. `/admin` calls `listDesigns()` directly, only for a signed-in admin, so the admin always sees the store as it is. Both pages fall back to an empty list on error. There is no public listing endpoint; do not add one without the cache.
- The cached listing is per Vercel environment: Production and Preview never share it. If Preview deployments use the same Blob store, a save or delete made there reaches Production's `/gallery` only at its next refresh, so moderate from Production.
- `/admin` checks the `admin_session` cookie with `isAdminSession()`. Signed out, it renders `AdminSignIn` (react-hook-form + zod + `Field`), which POSTs to `/api/admin/auth` and calls `router.refresh()`. Signed in, it renders `AdminGallery`, which deletes through `DELETE /api/gallery` (bulk delete runs the requests in parallel and keeps failed items selected) and signs out with `DELETE /api/admin/auth`.

### API Routes

All routes are Route Handlers and return errors as `{ error: string }`.

**Abuse limits** (`lib/rate-limit.ts`, `lib/client-address.ts`, `lib/same-origin.ts`)

- The three POST routes call `rejectCrossSite(request) ?? limitClient(...)` first, before reading the body: 10 generations per client at once, then one every 6 minutes; 5 gallery saves, then one every 12 minutes; 5 admin sign-in attempts, then one every 3 minutes. Over the limit they return `429` with `Retry-After` and a message.
- `limitGlobal()` enforces budgets shared by all clients: `generationBudget()` (200 a day) just before `replicate.run`, and `gallerySaveBudget()` (10 a day) just before `put()`. Only valid requests spend them, and `refundGlobal()` gives a generation back when Replicate refused to start it (401, 402). A budget of 0 turns the feature off: `turnedOff()` answers `503` with a "turned off" message before any work is done. When a budget is spent the server logs `Budget "<name>" (<n> a day) is spent.` at most once every 10 minutes, and an invalid value in the environment logs one warning and falls back to the default. The save budget protects the Blob quota, not availability: the per-client save limit is kept below it, but a few visitors can still use up the day. Each gallery save costs two Blob operations (the upload and the next listing), which is why the save budget is small. Admin sign-in has no shared budget, so that nobody can lock the admin out.
- The client is identified by `clientAddress()`: `x-real-ip` on Vercel (`VERCEL=1`), otherwise only the header named in `TRUSTED_IP_HEADER`. IPv6 addresses count by /64. When no trusted address is available, per-client limits are skipped rather than applied to everyone as one client.
- `rejectCrossSite()` returns `403` when `Sec-Fetch-Site` shows the request came from another site. Requests without that header (curl, tests) pass.
- These counters live in the server process: they are per instance and reset on deploy. They slow abuse down; the Vercel Firewall rule and the Replicate prepaid balance described in README > Abuse protection are what bound it. Do not present the in-process limits as a guarantee.

**`POST /api/replicate`** (`app/api/replicate/route.ts`)

- Body, validated with zod: `image` is a string of at most `MAX_IMAGE_DATA_URL_LENGTH` characters that starts with `data:image/png;base64,` or `data:image/jpeg;base64,`; `theme` is one of `DESIGN_THEMES`; `room` is one of `ROOM_TYPES`; `scale` is optional, `SCALE_MIN`..`SCALE_MAX` (0.1 to 30), default 9.
- `201 { output: string[] }`: output URLs. The client is created with `useFileOutput: false`, so `run()` returns plain URLs; with the SDK default every output would be wrapped in a `FileOutput` that downloads the image into server memory.
- `403` cross-site request; `503` generation turned off; `429` rate limit or daily budget reached; `400` invalid or unparseable body; `502` the model returned no output; `401` / `402` / `429` when Replicate's `ApiError` has that `response.status` (bad token, no credits, rate limit); `500 { error: message }` otherwise.
- Logs the prompt and the output URLs with `console.log`.

**`POST /api/gallery`** (no authentication)

- `403` for a cross-site request, `503` when saving is turned off and `429` over the per-client limit, all before the body is read; `429` when the daily save budget is spent.
- Body, validated with zod: `{ imageUrl: string, theme, room }` with the same enums; otherwise `400`.
- `imageUrl` must be `https:` on `replicate.delivery` or a subdomain (`ALLOWED_IMAGE_HOSTS`); otherwise `400`.
- The image is fetched with `redirect: "manual"`. Each `Location` is resolved and re-checked against the allowlist, up to 3 redirects. A rejected hop or a non-2xx response gives `400`.
- The body is read with a 10MB cap (declared `Content-Length` and streamed byte count), and the type is decided by magic bytes (PNG, JPEG or WebP); anything else gives `400`.
- Stored with `put(..., { access: "public", contentType })`. Returns `201 { url }`, or `500` on Blob errors or when the image request itself fails.

**`DELETE /api/gallery`** (admin only)

- `401 { error: "Unauthorized" }` without a valid `admin_session` cookie.
- Body `{ url }`: must be `https:`, on a host ending in `.public.blob.vercel-storage.com`, with a path under `/designs/`; otherwise `400`.
- `200 { success: true }`, or `500`.

**`POST /api/admin/auth`**: body `{ password }`. Returns `200 { ok: true }` and sets the session cookie, `403` for a cross-site request (checked before the rate limit, so it uses up no attempts), `401 { error: "Invalid password" }` (also when `GALLERY_ADMIN_SECRET` is unset), or `429` after too many attempts.

**`DELETE /api/admin/auth`**: deletes the cookie and returns `200 { ok: true }`.

**Admin session** (`lib/admin-session.ts`)

- `isAdminPassword()` compares SHA-256 digests of the submitted password and `GALLERY_ADMIN_SECRET` with `timingSafeEqual`.
- `createAdminSession()` returns `<expiresAt>.<hmac>`: `expiresAt` in epoch milliseconds, `hmac` the hex HMAC-SHA256 of `admin-session:<expiresAt>`. The HMAC key is derived from `GALLERY_ADMIN_SECRET` with scrypt (cached per process), so the cookie neither holds the password nor allows fast offline guessing of it.
- Cookie `admin_session`: `httpOnly`, `sameSite: "strict"`, `secure` in production, `path: "/"`, `maxAge` 7 days (`ADMIN_SESSION_MAX_AGE`).
- `isAdminSession()` checks the format, the expiry and the signature (constant time). It is used by `DELETE /api/gallery` and `app/admin/page.tsx`.

## Important Implementation Details

### Replicate API Integration

- Model: `jagilley/controlnet-hough:854e8727697a057c525cdb45ab037f64ecca770a1769cc52287c2e56472a247b`
- Inputs: `image` (the data URL), `prompt` from `buildPrompt(theme, room)`, `a_prompt` = `QUALITY_PROMPT`, `n_prompt` = `NEGATIVE_PROMPT`, `scale`.
- `buildPrompt` produces `A <theme> <room>, <THEME_KEYWORDS[theme]>, <ROOM_CONTEXT[room]>, Editorial Style Photo, Natural Light, 4k, Symmetry, Straight On`.
- `scale` is the guidance scale, shown as "Style Strength" presets: Faithful 4, Balanced 9, Creative 14, Bold 19. `SCALE_PRESETS` in `lib/constants.ts` holds the values, labels and descriptions; `components/style-presets.ts` adds the icons and is used by `design-controls.tsx` and the settings page. `SCALE_DEFAULT` (9) in `lib/constants.ts` is the default for both the settings and the API route, and must stay one of the presets.

### Security Configuration (`next.config.js`)

- `poweredByHeader: false`.
- `agentRules: false`: stops `next dev` from creating an `AGENTS.md` at the repo root when a coding agent runs it (default behaviour since Next 16.3). This file is the agent guide instead.
- Headers on every path: `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- `images.remotePatterns`: only `https://<store>.public.blob.vercel-storage.com/designs/**` with an empty `search`, so the optimizer serves saved designs and nothing else, and a query string cannot be used to optimize the same image again and again. `<store>` is this project's Blob store id, read from `BLOB_READ_WRITE_TOKEN` when the config loads (`blobStoreHostname()`; on Vercel that is build time); without a token it falls back to `*`. Replicate output is shown with a plain `<img>` by the comparison slider and never goes through `next/image`. The hosts a gallery save may fetch from are separate: `ALLOWED_IMAGE_HOSTS` in `app/api/gallery/route.ts`. The Blob domain is hard-coded twice, in `blobStoreHostname()` here and in `BLOB_HOST_SUFFIX` in that route (DELETE validation); change them together.

### Responsive Design

- `(main)/layout.tsx` sets `--sidebar-width: calc(var(--spacing) * 72)` and `--header-height: calc(var(--spacing) * 12)`; the sidebar uses `variant="inset"` and `collapsible="icon"`.
- On desktop the sidebar collapses to an icon rail (SidebarTrigger or Cmd/Ctrl+B). Below 768px (`useIsMobile`) it renders as a Sheet opened by the SidebarTrigger in `SiteHeader`.
- The Design page shows upload and output in two columns from `lg`; the gallery grids use 1, 2 (`sm`) and 3 (`xl`) columns.

### Performance Considerations

- Upload type and size are validated before the file is read into a data URL.
- The Generate button, comboboxes, presets and the photo's remove button are disabled while a generation runs. The request is aborted if the page unmounts.
- `/gallery` and `/admin` are `force-dynamic`; `/gallery` has a `loading.tsx` skeleton. The first three gallery images use `preload`.
- Saved designs render through `next/image` and must match `images.remotePatterns`.

### Deployment

`vercel.json` sets `bun install`, `bun run build` and the `nextjs` framework. `@vercel/analytics` is rendered in the root layout.

On Vercel the Route Handlers run on Node.js (the project's Node.js version; `vercel.json` sets no `bunVersion`). Bun only installs dependencies and runs `next build` there. `bun test` and `bun --bun next start` therefore do not exercise the production runtime: check anything runtime-specific on Node as well (`node node_modules/next/dist/bin/next start`).

## Testing

- `bun test` runs the suite in `tests/` on Bun's built-in runner (`bun:test`). There is no DOM test environment: the tests cover the API routes, `lib/`, `next.config.js` and what the `/gallery` and `/admin` pages load, not components or hooks. Keep logic worth testing in `lib/` (as `lib/settings.ts` does for `use-settings`).
- `tests/setup.ts` is the shared harness. `bunfig.toml` preloads it before every test file (`[test] preload`) and limits test discovery to `tests/`; test files import its exports. It sets dummy credentials, mocks `@vercel/blob`, `replicate`, `next/headers` and `next/cache`, replaces `fetch` with a mock that throws for any URL a test did not register, resets all of that around every test, and exports the mock state (`blob`, `replicate`, `network`, `cookieJar`, `nextCache`) and request helpers. Requests built by `jsonRequest()` carry no client address, so per-client limits only apply to tests that pass an `x-real-ip` header; rate-limit counters are reset before every test. No test may reach a real service.
- Load route modules (and `lib/gallery.ts`) with `await import(...)` after the setup import so they pick up the mocks. Keep test files in `tests/`: a `*.test.ts` elsewhere is not run and would break `tsc` for the app.
- The fetch mock returns one branch of a tee'd body, as Next.js does for route handlers. Never `await` `body.cancel()` / `reader.cancel()` on a fetched response in a route: it does not settle and the request hangs (see `discardBody` in `app/api/gallery/route.ts`).
- When you change a route, `lib/` module or `next.config.js`, update or add tests in the matching `tests/*.test.ts` file and run `bun test` and `bun run typecheck`.

## Common Development Patterns

When adding new features:

- Keep state in the component that owns it; use `DesignContext` only for what the sidebar needs.
- Use `useCallback` where a handler is a hook dependency or is passed to a hook (as on the Design page and in `use-dropzone`); plain function declarations elsewhere.
- Use the shadcn/ui components in `components/ui/` and `cn()` from `lib/utils`.
- Use Tailwind utilities; avoid inline styles unless dynamically computed.

When modifying API routes:

- Parse the body with `await request.json().catch(() => null)` and validate it (zod `safeParse` for structured bodies) before any side effect.
- Return `{ error: string }` on failure. Status codes in use: 201 on create, 200 otherwise, 400 invalid input, 401 unauthenticated, 403 cross-site request, 429 rate limited, 503 feature turned off, 502 empty upstream output, 500 unexpected errors.
- A new public POST route starts with `rejectCrossSite(request) ?? limitClient(<limit>, request)`, before reading the body. A route that spends money or quota also takes from a global budget with `limitGlobal()` right before the spending call.
- After changing what `/gallery` lists (a save or delete), call `revalidateDesigns()`.
- For server-side fetches of user-supplied URLs, parse with `new URL`, check the host against an allowlist, fetch `url.href` with `redirect: "manual"` and re-check every hop (see `fetchAllowedImage` in `app/api/gallery/route.ts`).
- Log with `console.log` / `console.error`; the lint config allows it.

## Dependency Maintenance

- Bun only. `bunfig.toml` sets `minimumReleaseAge = 604800`, so new resolutions skip versions published less than 7 days ago (versions already in `bun.lock` are unaffected). Never run `bun audit fix`: per https://bun.com/docs/install/audit it can install a fixed version newer than the minimum release age. Upgrade with `bun add` / `bun update`, then run `bun audit`. For an urgent security release younger than 7 days, exempt only that version once: `bun add -E <pkg>@<version> --minimum-release-age-excludes=<pkg>@<version>`, and say so in the commit message.
- `next`, `react`, `react-dom`, `lucide-react` and `replicate` are pinned to exact versions. Keep them exact with `bun add -E <package>@<version>`, and move `react` and `react-dom` together.
- `@vercel/blob` is held at exactly 2.3.3. From 2.4.1 it depends on `@vercel/oidc` → `@vercel/cli-config`, which (as of `@vercel/blob` 2.9.0 / `@vercel/oidc` 3.8.10) pins and bundles `zod` 4.1.11 (GHSA-mrhx-c7xc-m3w5) and makes every `put` / `list` / `del` try a Vercel OIDC token lookup before reading `BLOB_READ_WRITE_TOKEN`. Upgrade once `@vercel/blob` depends on an `@vercel/oidc` release whose `@vercel/cli-config` uses `zod` >= 4.6.6 (`@vercel/oidc` 4.0.9 does); after upgrading, check `bun why zod` and `bun audit`, and pass `token: process.env.BLOB_READ_WRITE_TOKEN` to the Blob calls to skip the OIDC lookup.
- Next.js ships version-matched docs in `node_modules/next/dist/docs/`. Read them before using a Next.js API; the installed version is newer than most training data.
- TypeScript stays on 6.x (`^6.0.3`) until the Next.js TypeScript plugin (`plugins: [{ "name": "next" }]` in `tsconfig.json`) supports TypeScript 7.
- `bunfig.toml` (project root) configures installs and `bun test`. A dot-prefixed `.bunfig.toml` is only read from the home directory, never from a project.
- `trustedDependencies` is `["sharp"]`. sharp is a dev dependency for `scripts/generate-icons.ts` and is also what `next` uses for image optimization.
